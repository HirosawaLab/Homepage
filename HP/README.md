## 1. 全体概要

### 運用方針

```
教授からメール
    ↓
管理担当者がこのフォルダをCursor / Codex / Claude Codeなどで開く
    ↓
教授からのメール本文をそのままAIエージェントに送信
    ↓
AIが docs/knowledgebase.md を参照してどの更新パターンか判別（P1〜P16）
    ↓
AIが変更差分をユーザーに見せる（最終確認）
    ↓
ユーザーが変更してもいいと答える（最終確認）
    ↓
AIが該当ファイルを自動編集（ルール集A〜Eも遵守）
    ↓
管理担当者が差分を確認してサーバーにアップロード
```

### AIが自動で判断・実行すること

- 教授のメール内容から更新パターン（P1〜P16）を判別
- 変更内容の整理・提示（承認待ち）
- 承認後：対象ファイルの特定と編集
- 日付・カテゴリ・本文・リンクの正確な記述（ルール集A〜E準拠）
- 複数パターンが混在する場合の一括処理
- ニュース追加後に index.html が10件超えていれば自動で古い記事を削除（P11）
- 年が変わる最初の記事追加時は新年セクションを自動追加（P7）

### 管理担当者がすること

- このフォルダをAIエージェントで開き、メール本文をそのまま送る
- AIが提示した変更内容を確認し、「OK」または「実行して」と返答する
- アルバムの場合、画像ファイルを `album/（フォルダ名）/` に配置する
- AIの編集完了後、変更ファイルをサーバーにアップロードする

### 更新パターン一覧

| # | パターン名 | 発生頻度 |
|---|---|---|
| P1 | ニュース記事の追加 | 高（随時） |
| P2 | ニュース記事の修正 | 中（随時） |
| P3 | メンバーの追加・削除・学年変更 | 中（随時） |
| P4 | アルバムの新規作成・登録 | 中（随時） |
| P5 | 既存アルバムへの写真追加 | 低（随時） |
| P6 | 論文・研究業績の追加 | 中（随時） |
| P7 | 新年セクションの追加 | 年1回（1月〜） |
| P8 | 年度切り替え（4月の一斉更新） | 年1回（4月） |
| P9 | 現在形→過去形の手動修正 | 低（随時） |
| P10 | PDF・チラシのアップ＋ニュースリンク | 低（随時） |
| P11 | index.htmlの古いニュース削除 | P1実行後に自動判定 |
| P12 | アルバム個別ページの内容修正 | 低（随時） |
| P13 | Album.html既存エントリの修正 | 低（随時） |
| P14 | トップページのメイン画像差し替え | 低（随時） |
| P15 | リンクページの更新 | 低（随時） |
| P16 | 研究紹介ページの更新 | 低（随時） |

> 詳細は `docs/knowledgebase.md` を参照。

## 3. 基本の使い方（AGENTS.md 運用）

現在は `AGENTS.md` にAIエージェント向けの作業指示をまとめている。
Cursor / Codex / Claude Code などのコーディングエージェントでこのフォルダを開き、教授からのメール本文をそのままチャット欄に貼り付けて依頼すればよい。

---

```
（ここに教授からのメール本文をそのまま貼り付ける）
```

---

旧運用で使っていた `prompt/` フォルダは廃止済み。
エージェントは `AGENTS.md` と `docs/knowledgebase.md` を参照して作業する。

## 4. 手動編集後のダブルチェック

HTMLを直接手動で編集した後、AIにチェックを依頼する際に使う。
確認してほしいファイル名をそのまま書いて送信する。

---

```
News.html をダブルチェックしてください。
```

必要に応じて、`album/202603311938/main.html` のようにチェック対象ファイルを指定する。

## 5. 使用例


### 例1：ニュース記事の追加（学会発表）

**教授からのメール：**
```
2026.5.10-11　「学会」
第149回軽金属学会春期大会（於 東京工大）で口頭発表します（M2：近藤、中野）
→ リンク：https://www.jilm.or.jp/convention/index
```

**AIの応答（P1）：**

まず変更内容を提示：

```
【実行予定の変更】

■ News.html　← P1
  概要：2026年セクション先頭に学会発表記事を追加
  ```diff
  + <li>
  +   <time datetime="2026-5-10">2026.5.10-11</time>
  +   <span class="category">学会</span>
  +   <p><a href="https://www.jilm.or.jp/convention/index">第149回軽金属学会春期大会（於 東京工大）</a>で口頭発表します（M2：近藤、中野）</p>
  + </li>
  ```

■ index.html　← P1
  概要：同内容をトップページ先頭に追加（7件 → 8件、P11不要）
  ```diff
  + <li>
  +   <time datetime="2026-5-10">2026.5.10-11</time>
  +   <span class="category">学会</span>
  +   <p><a href="https://www.jilm.or.jp/convention/index">第149回軽金属学会春期大会（於 東京工大）</a>で口頭発表します（M2：近藤、中野）</p>
  + </li>
  ```

上記の変更を実行してよいですか？
```

ユーザーが「OK」と返答後に編集実行。

---

### 例2：アルバムの追加（フォルダ未作成の場合）

**教授からのメール：**
```
先日の学会のアルバムを追加してください。
タイトル：第149回軽金属学会春期大会
日付：2026.5.10-11
説明：口頭発表しました（M2：近藤、中野）
```

**AIが自動で行う作業（P4 ケースB）：**
1. フォルダ `album/202605110000/` を自動作成
2. 「写真ファイルをフォルダに追加してください。完了したら教えてください」と一時停止
3. 完了報告を受けたら `main.html` を作成し `Album.html` に登録

---

### 例3：年度切り替え（4月）

**教授からのメール：**
```
新年度のメンバー更新をお願いします。
卒業・修了：M2の川名、楠本、B4の須長
進級：M1→M2（橋本）、B4→M1（浜田、長谷川、二ッ森）
新B4：山田一郎、佐藤花子、田中次郎

ニュースも追加してください。
2026.4.7　「その他」
研究室に新メンバーを迎えました（M1：浜田、長谷川、二ッ森、B4：山田、佐藤、田中）
```

**AIが自動で行う作業（P8＋P1）：**
- 卒業・修了者を `Member.html` から削除
- 残留メンバー全員の学年を1つ上げる
- 新B4を `Member.html` に追加
- ニュース記事を `News.html`・`index.html` に追加

---

### 例4：複数パターン混在（ニュース＋アルバムリンク追記）

**教授からのメール：**
```
2026.5.10-11の学会発表のニュースにアルバムリンクを追加してください。
アルバムフォルダ：202605110000
```

**AIが自動で行う作業（P2＋P4）：**
- `album/202605110000/` 内のファイルを確認して `main.html` を作成（P4）
- `News.html`・`index.html` の該当記事末尾にアルバムリンクを追記（P2）
- `Album.html` の一覧先頭に登録（P4）

---

### 例5：年が変わる最初のニュース追加

**教授からのメール：**
```
2027.1.15　「論文」
軽金属誌に受理された学術論文が公開されました
→ リンク：https://example.com
```

**AIが自動で行う作業（P7＋P1）：**
- `News.html` に `<h2 id="2027y">2027年</h2>` と `<ul>` ブロックを追加（P7）
- その中に `<li>` を追加（P1）
- `index.html` に同内容を追加し、10件超えなら末尾削除（P1＋P11）

## 6. CIチェック

PR作成時と `main` への push 時に、GitHub Actions の `HP CI` が自動で実行される。
構文ミスや `docs/knowledgebase.md` の基本ルール違反を、公開前に検知するための仕組み。

ローカルでも同じチェックを実行できる。

```bash
python tools/validate_hp.py
```

主に以下を確認する。

- 管理対象HTMLの基本的なタグ対応
- `News.html` の最新年セクションと `index.html` の日付表記
- ニュースカテゴリが `論文`・`学会`・`受賞`・`その他` の4種類に収まっているか
- `index.html` のニュースが10件以内か
- 管理対象HTMLから参照するローカル画像・PDF・ページが存在するか

`album/` は Git 管理外の大容量フォルダなので、GitHub Actions 上ではリンク存在チェックの対象外。
アルバムの実ファイル確認は、これまで通り作業時にエージェントがローカルで行う。

## 7. CDデプロイ

`main` ブランチで `HP CI` が成功すると、GitHub Actions の `HP Deploy` が起動し、SFTP で `/public_html/` に自動アップロードする。
FileZillaで使っている接続先に、GitHub Actions から直接アップロードする仕組み。

GitHub の Repository Secrets には以下を設定する。

| Secret名 | 値 |
|---|---|
| `FTP_HOST` | SFTPホスト名またはIPアドレス |
| `FTP_USERNAME` | SFTPユーザー名 |
| `FTP_PORT` | 通常は `22` |
| `FTP_PASSWORD` | SFTPパスワード |

本番反映なので、GitHub の `production` Environment に required reviewers を設定しておくと安全。
その場合、`HP Deploy` は承認後にアップロードを実行する。

CDで自動アップロードするものは、GitHubで管理されているHTML、CSS、JavaScript、画像、PDFなど。
内部管理用ファイルや大容量の Git 管理外フォルダはアップロードしない。

除外対象:

- `docs/`
- `tools/`
- `AGENTS.md`
- `CLAUDE.md`
- `README.md`
- `album/`
- `oldsite/`

`album/` は `.gitignore` 対象でGitHub上に存在しないため、アルバム追加時は従来通り FileZilla 等で手動アップロードする。

## 8. 更新後の公開作業

AIによる編集が完了し、PRを `main` にマージすると、通常のHTML更新はCDで自動アップロードされる。
ただし、`album/` のような Git 管理外ファイルは手動アップロードが必要。

| 作業内容 | アップロードするもの |
|---|---|
| ニュース追加・修正 | `News.html`、`index.html` |
| メンバー変更・年度切り替え | `Member.html` |
| アルバム追加 | `Album.html`、`album/（フォルダ名）/` フォルダ一式 |
| 論文追加 | `Publication.html` |
| PDFリンク追加 | `News.html`、`index.html`、`image/（ファイル名）.pdf` |
| トップ画像差し替え | `index.html`、`images/（画像ファイル）` |
| リンク更新 | `Link.html` |
| 研究紹介更新 | `Research.html`、`Research_EN.html` |

手動アップロードにはFTPクライアント（WinSCP、FileZilla等）を使用する。
**手動でアップロードする場合は変更したファイルのみ**アップロードすれば足りる（全体を上書きしない）。

## 9. ルールと規約

詳細なルールはすべて `docs/knowledgebase.md` のルール集（A〜E）に記載している。
ここでは特に重要なものを抜粋する。

### 日付表記

- `datetime` 属性：`YYYY-M-D`（ゼロなし）例：`datetime="2026-3-9"`
- 表示テキスト：`YYYY.M.D` 例：`2026.3.9`
- 期間：`2026.2.21-23`（終日のみ短縮）

### ニュース本文

- イベント日が過ぎている場合は、本文を直接過去形で書く
- 未来の予定は現在形・未来形で書いてよいが、日付経過後に必要なら手動で過去形へ直す

### ページ管理

- `index.html` のニュースは**10件まで**（超えたら古いものを削除）
- `News.html` は全件保持（削除しない）
- アルバムフォルダ名 `YYYYMMDDhhmm` は一度決めたら変更しない

### カテゴリ

`論文`・`学会`・`受賞`・`その他` の4種類のみ使用する。
