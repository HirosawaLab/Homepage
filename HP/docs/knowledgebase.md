# 廣澤研究室 HP 更新パターン集

AIが依頼メールを受け取ったとき、このファイルを参照して**どのパターンに該当するか**を判別する。

**編集の流れ：**
1. パターンを判別する
2. 変更内容をユーザーに提示して承認を得る（この時点ではファイルを編集しない）
3. 承認後にファイルを編集する

## P1：ニュース記事の追加

### 編集対象ファイル

| ファイル | 必須/任意 | 内容 |
|---|---|---|
| `News.html` | **必須** | ニュース一覧ページ |
| `index.html` | **必須** | トップページの最新情報欄 |

### News.html の編集手順

1. 対象の年の `<ul class="news-list">` を探す
2. 日付の降順（新しいものが上）になる位置に `<li>` を挿入する
3. その年のセクションがまだ存在しない場合は、既存の年セクションより上に以下を追加：
   ```html
   <h2 class="label" id="20XXy">20XX年</h2>
   <ul class="news-list">
     <!-- ここに <li> を追加 -->
   </ul>
   ```

**`<li>` の基本形：**
```html
<li>
  <time datetime="YYYY-M-D">YYYY.M.D</time>
  <span class="category">カテゴリ</span>
  <p>本文テキスト</p>
</li>
```

**URLリンクあり：**
```html
<p><a href="https://example.com">リンクテキスト</a>で口頭発表します（M2：○○）</p>
```

**アルバムリンクあり：**
```html
<p>本文テキスト　<a href="album/202604010000/main.html">アルバム</a></p>
```

**カテゴリの種類：**
- `論文` — 論文掲載・受理
- `学会` — 学会発表・参加
- `受賞` — 受賞
- `その他` — 上記以外

> **受賞・表彰カテゴリの場合：** 変更内容を提示する前に「コメントはどのようにされますか？（例：○○さん、受賞おめでとうございます！）」とユーザーに確認し、返答を得てからdiffに反映すること。

**現在形・未来形→過去形への変換は手動で行う：**
`js/tense.js` は削除済み。日付が過ぎたら `<p>` 内のテキストを直接過去形に書き換えること。
例：「口頭発表します」→「口頭発表しました」

### index.html の編集手順

`News.html` と同一の `<li>` を `<ul>` 内の先頭に挿入する。
トップページは**直近10件程度**を目安に掲載。古くなったものは削除してよい。


## P4：アルバムの新規作成・登録

### 編集対象ファイル

| ファイル | 必須/任意 | 内容 |
|---|---|---|
| `album/（フォルダ名）/main.html` | **必須（新規作成）** | アルバム個別ページ |
| `Album.html` | **必須** | アルバム一覧への登録 |
| `News.html` | 任意 | 対応するニュース記事にアルバムリンクを追記 |
| `index.html` | 任意 | 対応するニュース記事にアルバムリンクを追記 |

### フォルダ命名規則

```
YYYYMMDDhhmm
例：202604011423（2026年4月1日 14:23 にAIが編集作業を行った）
```

フォルダ名はイベント日付ではなく、**AIが編集作業を実施した日時（現在日時）** を使う。

フォルダ名が指定されていない場合は、**現在の日時**を使って自動生成する。

---

### 実行フロー

#### 通常フロー（新規アルバム作成の標準手順）

1. 変更内容をユーザーに提示して承認を得る（手順3の確認ステップ）
2. 承認後、`album/（フォルダ名）/` フォルダを作成する
3. ユーザーに以下を伝えて**一時停止する**：

   ```
   アルバムフォルダ `album/（フォルダ名）/` を作成しました。
   写真ファイルをこのフォルダに追加してください。
   追加が完了したら「完了しました」と入力してください。
   その後、main.html の作成と Album.html への登録を行います。
   ```

4. ユーザーから完了の返答を受け取ったら、フォルダ内のファイル一覧を確認する
5. `main.html` を作成する（下記テンプレート参照）
6. `Album.html` の一覧先頭に登録する

> **注意：** `Album.html` への登録（サムネイル含む）は**写真追加完了の確認後**に行うこと。写真がない状態で先行登録しない。

#### 例外フロー（フォルダと画像がすでに存在する場合）

ユーザーから「フォルダ `（名前）` に写真を入れました」と事前に伝えられた場合：

1. `album/（フォルダ名）/` 内の画像ファイル一覧を確認する
2. `main.html` を作成する
3. `Album.html` の一覧先頭に登録する

---

### main.html の作成

既存の `album/202603262017/main.html` をテンプレートとしてコピーし、以下を変更：

```html
<!-- パンくずリストの日付 -->
<div class="bread-list">
  ... ＞ YYYY.M.D   ← イベント日付
</div>

<!-- タイトル -->
<h2 class="label">（イベント名）</h2>

<!-- 説明文 -->
<p>（説明）</p>

<!-- 写真リスト：フォルダ内の画像ファイルをすべて列挙 -->
<ul>
  <li><a href="1.jpg"><img src="1.jpg" alt="photo1"></a></li>
  <li><a href="2.jpg"><img src="2.jpg" alt="photo2"></a></li>
</ul>
```

**フォルダ内にPDFファイルがある場合：** `<ul>/<li>` を使わず、`<iframe>` と `<a>` で直接埋め込む：
```html
<!-- <ul> は不要。article 内に直接書く -->
<iframe src="1.pdf" width="100%" height="700px" style="border:none;"></iframe>
<p><a href="1.pdf">PDFをダウンロード</a></p>
```

> **重要：** `album/（フォルダ名）/` 内のファイル一覧を実際に確認し、存在するファイルをすべて列挙すること。ファイル名は実際のものを使うこと。

### Album.html への登録

**画像ファイルの場合：**
```html
<li><a href="./album/（フォルダ名）/main.html">（タイトル）<br>(YYYY.M.D)<br><br><img src="./album/（フォルダ名）/（サムネイル画像）"></a></li>
```

**PDFファイルの場合：** `<img>` の代わりに `<object>` を使う：
```html
<li><a href="./album/（フォルダ名）/main.html">（タイトル）<br>(YYYY.M.D)<br><br><object data="./album/（フォルダ名）/（ファイル名）.pdf" type="application/pdf" style="pointer-events:none; width:100%; height:150px;"></object></a></li>
```

> `pointer-events:none` により、`<object>` 上のクリックが `<a>` に伝わり、main.html へ遷移できる。

## P8：年度切り替え（4月の一斉更新）

### 発生タイミング

毎年4月。新学期のメンバー体制が確定した時点で実行する。

### 編集対象ファイル

| ファイル | 必須/任意 | 内容 |
|---|---|---|
| `Member.html` | **必須** | 全メンバーの学年更新・入退室 |
| `News.html` | **必須** | 新メンバー迎えた旨のニュース追加（P1） |
| `index.html` | **必須** | 同上（P1） |

### 編集手順

以下をすべて実行する（P3の一括版）：

1. **卒業・修了者を削除** — 前年度のB4・M2・D3（修了する人）を `Member.html` から削除
2. **全員の学年を1つ上げる** — D2→D3、M1→M2、B4（残留）→そのまま等
3. **新入生を追加** — 新M1（前年度B4）、新B4を追加
4. **ニュース記事を追加** — 「研究室に新メンバーを迎えました」記事をP1で追加

> 学年変更対象・入退室リストは必ず教授のメールで確認してから実行すること。

> **曖昧な指示がある場合はユーザーに確認を求めること。** 例：メールに記載された学生名が現在の `Member.html` と一致しない（名前が見当たらない・学年が矛盾する）場合は、処理を中断し「○○さんは現在の名簿に見当たりません。確認してください」と伝えること。勝手に補完・推測して編集しない。

# サイト固有ルール集

AIはニュース記事を作成・修正する際、以下のルールをすべて遵守すること。

---

## 【A】日付の表記ルール

| ルール | 正しい例 | 誤った例 |
|---|---|---|
| `datetime` 属性はゼロなし `YYYY-M-D` | `datetime="2026-3-9"` | `datetime="2026-03-09"` |
| 表示テキストはドット区切り `YYYY.M.D` | `2026.3.9` | `2026-3-9` |
| 期間は終日のみ短縮 | `2026.2.21-23` | `2026.2.21-2.23` |
| `datetime` の期間指定 | `datetime="2025-11-7-9"` | — |

---

## 【B】ニュース本文の命名規則

### 学会発表

```
（会議名）（於 開催地）で口頭発表しました（役職：氏名）
（会議名）（於 開催地）でポスター発表しました（役職：氏名）
（会議名）（於 開催地）で口頭発表（役職：氏名）、ポスター発表（役職：氏名）しました
```

### 招待講演・セッション主宰

```
（会議名）のセッション名セッションで招待講演しました（廣澤）
（会議名）でキーノート講演しました（廣澤）
（会議名）でセッション名を主宰します（廣澤）　← 未来形OK（自動変換される）
```

### 受賞

```
（賞名）を受賞しました（役職：氏名）
（会議名）で発表し、（賞名）を受賞しました（役職：氏名）　← 発表と受賞の複合
```

受賞・表彰のアルバムページ（`main.html`）には、説明文 `<p>` の**直後**に必ずお祝いコメントの `<p>` を追加すること：

```html
<p>（賞名）を受賞しました（役職：氏名）</p>
<p>（氏名）さん、受賞おめでとうございます！</p>
```

コメント文はユーザーに確認した内容をそのまま使うこと（上記は例）。

### 論文掲載

```
（雑誌名）に受理された学術論文が公開されました
（雑誌名）誌に解説「（タイトル）」が掲載されました（廣澤）
```

### メンバー関連

```
研究室に新メンバーを迎えました（M2：○○、M1：△△、B4：□□、▲▲）
研究室にROUTE学生として新メンバーを迎えました（B1：○○）
研究室から新たな世界にはばたくメンバーを送り出しました（M2：○○、B4：△△）
```

### その他

```
（セミナー名）（於 開催地 要参加申込）で講師を務めました（廣澤）
（セミナー名）　参加者募集　← 未来形OK（自動変換される）
（氏名）氏の博士論文公聴会が開催されました
```

## 【C】メンバー表記ルール

| ルール | 例 |
|---|---|
| 学年表記 | `D1〜D3`（博士）、`M1〜M2`（修士）、`B1〜B4`（学部） |
| 複数人は読点区切り | `（M2：近藤、中島）` |
| 複数役職は役職ごとに括弧 | `口頭発表（D1：森野）、ポスター発表（M1：近藤、中島）` |
| ROUTEプログラム学生 | 「ROUTE学生として」を本文に含める |
| 廣澤教授 | `（廣澤）` — 役職省略 |

## 【D】リンク・書き方ルール

| ルール | 例 |
|---|---|
| アルバムリンクは本文末尾に全角スペース1つ区切り | `〜しました　<a href="album/...">アルバム</a>` |
| 外部URLリンクは文頭側のテキストに付ける | `<a href="URL">会議名</a>で発表しました` |
| 開催場所 | `（於 横浜国大）`、`（於 韓国昌原）` — 全角括弧、「於」後に半角スペース |
| オンライン開催 | `（オンライン開催）` または `（オンライン参加は要申込）` |
| 要申込 | `（要参加申込）` または `（於 東京 要参加申込）` — 場所と併記 |
| PDFリンク先 | `./image/ファイル名.pdf` |

## 【E】ページ管理ルール

| ルール | 詳細 |
|---|---|
| index.htmlのニュースは**10件まで** | 超えたらP11を実行して末尾を削除 |
| News.htmlは全件保持 | 古い記事も削除しない |
| アルバムフォルダ名は `YYYYMMDDhhmm` | AIが編集を実施した日時。一度決めたら変更しない（URLになるため） |
| Album.htmlは最新順 | 先頭が最新、末尾が最古 |
| カテゴリは4種類 | `論文`・`学会`・`受賞`・`その他` |
| `album/info_morino.html` は要確認 | 下記【G】参照 |
| `docs/`・`AGENTS.md`・`CLAUDE.md` はアップロード禁止 | 内部管理ファイルのため、Webサーバー（FileZilla）にアップロードしないこと |

## 【G】個人ページの編集ルール

`album/info_morino.html` は森野さん（D2）が内容にこだわりを持つ個人ページであるため、以下のルールを守ること：

- **内容の変更・追加・削除は必ず森野さん本人に確認してから実施すること**
- HP係経由で依頼があった場合も、「森野さんご本人からの依頼ですか？」と確認を取ること
- 技術的な修正（画像パスの更新・スクリプトタグの追加等）は確認不要だが、テキスト・論文リスト・受賞歴等の内容変更は本人確認必須

## 【F】ナレッジの自動更新ルール

作業中に以下のいずれかを発見した場合、**ユーザーへの承認確認なしに** `docs/knowledgebase.md` への追記を自動で行うこと：

- 既存パターン（P1〜P16）に当てはまらない新しい更新作業が発生した
- 実際のHTMLから、このファイルに記載されていない表記・構造のルールが読み取れた
- ユーザーから「〜のようにしてほしい」と指示された運用ルールが生まれた

### 追記の方法

| ケース | 追記先 |
|---|---|
| 新しい更新パターン | パターン一覧表に追加 ＋ 末尾に詳細セクションを追記 |
| 既存パターンへの補足 | 該当パターンのセクション内に追記 |
| サイト固有のルール | 【A】〜【E】の該当ルール集に追記、なければ新しいルール集を追加 |

> 追記後、「`docs/knowledgebase.md` にルールを追加しました：（内容の一言要約）」とユーザーに報告すること。
